# VigorSync 接口与数据契约

## 1. 通用约定

- Core API 基础路径：`/api/v1`。
- Live Engine 本地基础路径：`http://127.0.0.1:8020`。
- 时间：数据库和 API 使用 UTC ISO 8601；视频内事件同时携带相对毫秒 `t_ms`。
- ID 规则：
  - `session_id`：`^s_[A-Za-z0-9_-]{6,64}$`
  - `job_id`：`^job_[A-Za-z0-9_-]{6,64}$`
  - `rep_id`：`^r_[A-Za-z0-9_-]{4,64}$`
  - 前缀后的随机部分必须不可预测，不能使用自增序号。
- 客户端命令必须携带幂等键：`Idempotency-Key`。
- 所有错误使用统一响应：

```json
{
  "error": {
    "code": "session_not_active",
    "message": "当前会话不在可暂停状态",
    "details": {},
    "request_id": "req_123"
  }
}
```

- 手机访问 Core API 时使用 `Authorization: Bearer <pairing_token>`。
- Live Engine 只监听 `127.0.0.1`，不直接对局域网开放。

## 2. 端口与信任边界

| 服务 | 端口 | 暴露范围 | 说明 |
| --- | --- | --- | --- |
| `core-api` | 8011 | 局域网 | 手机和镜端访问 |
| `live-engine` | 8020 | 本机回环 | 摄像头、预览、实时状态 |
| `offline-worker` | 8030 | 本机回环 | RepChain、问题卡、证据报告 |
| `mirror` | 8080 | 本机或局域网 | Kiosk UI |
| `report-web` | 由 Core 托管 | 局域网 | 详细报告 |

高帧率视频和骨架只经过 Live Engine 与镜端之间的本机回环。手机只接收低频摘要。

## 3. Core API

### 3.1 健康检查

```http
GET /api/v1/health
```

```json
{
  "status": "ok",
  "version": "0.1.0",
  "live_engine": "ok",
  "offline_worker": "ok"
}
```

### 3.2 手机配对

```http
POST /api/v1/pairing/claim
Content-Type: application/json
```

```json
{
  "pairing_code": "482913",
  "device_name": "Pixel 8",
  "platform": "android"
}
```

响应：

```json
{
  "token": "pair_xxx",
  "core_url": "http://192.168.1.20:8011",
  "expires_at": "2027-01-01T00:00:00Z"
}
```

第一版使用短期配对码换取长期设备 token。token 只存手机安全存储，不写入日志。

### 3.3 创建会话

```http
POST /api/v1/sessions
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

```json
{
  "exercise": "squat",
  "view": "side_left",
  "target_reps": 12,
  "notes": null
}
```

`exercise` 第一版只允许 `squat`、`pushup`。`view` 使用现有动作契约的枚举。

响应：

```json
{
  "session_id": "s_01JABC123",
  "status": "created",
  "exercise": "squat",
  "view": "side_left",
  "target_reps": 12,
  "notes": null,
  "created_at": "2026-11-15T10:00:00Z",
  "started_at": null,
  "ended_at": null,
  "job_id": null,
  "report_url": null,
  "live_summary": null,
  "error": null
}
```

### 3.4 启动、暂停、恢复、停止

```http
POST /api/v1/sessions/{session_id}/start
POST /api/v1/sessions/{session_id}/pause
POST /api/v1/sessions/{session_id}/resume
POST /api/v1/sessions/{session_id}/stop
POST /api/v1/sessions/{session_id}/cancel
Authorization: Bearer <token>
Idempotency-Key: <uuid>
```

合法状态迁移：

```text
start:  created|preparing -> preparing
pause:  active -> paused
resume: paused -> active
stop:   active|paused -> stopping
cancel: created|preparing|active|paused -> cancelled
```

重复调用相同幂等键必须返回同一结果，不得重复启动或重复创建 job。

完整迁移表以 `packages/contracts/session-state-machine.json` 为准。除下列命令迁移外，Live Engine 和 Core 只允许以下内部迁移：

```text
preparing -> active:     internal.live_ready
stopping -> analyzing:   internal.finalize_accepted
analyzing -> completed:  internal.report_ready
created|preparing -> failed:  internal.start_failed
active|paused -> failed:      internal.runtime_failed
stopping -> failed:           internal.finalize_failed
analyzing -> failed:          internal.analysis_failed
```

`completed`、`failed`、`cancelled` 为终态，不允许再迁出。`stopping` 和 `analyzing` 不接受用户取消，必须先完成失败或分析流程。

### 3.7 报告

```http
GET /api/v1/sessions/{session_id}/report
```

```json
{
  "session_id": "s_01JABC123",
  "job_id": "job_abc123",
  "status": "completed",
  "report_url": "/reports/jobs/job_abc123/report.html",
  "summary": {
    "rep_count": 12,
    "rejected_rep_count": 1,
    "quality_status": "limited",
    "active_issue_count": 3
  }
}
```

分析进行中，会话 `analysis` 对象会携带 `job_id`、`stage` 和 `progress`。
报告完成后的 `summary` 还包含问题卡摘要，响应字段为：

```json
{
  "status": "completed",
  "rep_count": 5,
  "rejected_rep_count": 0,
  "duration_s": 18.4,
  "quality_status": "pass",
  "active_issue_count": 2,
  "severity_counts": {"high": 1, "medium": 1, "low": 0},
  "mean_confidence": 0.91,
  "issues": []
}
```

`report_url` 是高熵票据路径。Core 负责代理报告 HTML、视频和证据帧，Worker
端口不对局域网开放。

### 3.8 删除媒体

```http
DELETE /api/v1/sessions/{session_id}/media
Authorization: Bearer <token>
```

只删除原始视频和关键点，默认保留派生报告；请求参数 `include_report=true` 可一并删除。

### 3.9 手机到镜端的配置与控制

手机首页每次改变动作、机位或目标次数后，向 Core 发送最新草稿配置：

```http
POST /api/v1/control/config
Authorization: Bearer <pairing_token>
Content-Type: application/json

{
  "exercise": "squat",
  "view": "front",
  "target_reps": 12
}
```

Core 将配置广播为 `session.config`。镜端启动时也可通过本机
`GET /dev/v1/config` 获取最近一次配置。

手机启动训练时使用单次幂等接口，避免“创建会话”和“启动会话”两次串行往返：

```http
POST /api/v1/sessions/start
Authorization: Bearer <pairing_token>
Idempotency-Key: <key>

{
  "exercise": "squat",
  "view": "front",
  "target_reps": 12
}
```

训练结束后，手机在用户点击“返回主页”时发送：

```http
POST /api/v1/sessions/{session_id}/mirror/dismiss
Authorization: Bearer <pairing_token>
```

该请求不改变会话状态，只广播 `session.dismissed`，让镜端从总结页返回配置页。
仍在训练中的会话不能 dismiss。

### 3.11 离线任务

训练停止后 Core 创建 `job_*` 并调用本机：

```http
POST http://127.0.0.1:8030/internal/v1/jobs
X-Internal-Token: <offline-token>
```

Worker 生成报告后，Core 向手机与镜端广播 `report.progress` 和
`report.ready`。详细实现见 `services/offline-worker/README.md`。

### 3.10 完整删除会话

```http
DELETE /api/v1/sessions/{session_id}
Authorization: Bearer <pairing_token>
```

仅允许删除已结束的会话。Core 会依次校验 session 目录、删除本机目录、删除会话与
事件记录，并广播 `session.deleted`。训练中、准备中或已暂停的会话返回 `409`。

## 4. Live Engine 内部接口

Core 与 Live Engine 之间的内部请求必须携带 `X-Internal-Token`，并只允许本机回环访问。

### 4.1 启动

```http
POST /internal/v1/sessions/{session_id}/start
Content-Type: application/json
X-Internal-Token: <internal-token>
```

```json
{
  "exercise": "squat",
  "view": "side_left",
  "target_reps": 12,
  "session_dir": "/data/sessions/s_01JABC123"
}
```

响应：

```json
{
  "session_id": "s_01JABC123",
  "status": "preparing",
  "stream_url": "http://127.0.0.1:8020/live/s_01JABC123/stream.mjpg",
  "ws_url": "ws://127.0.0.1:8020/ws/live/s_01JABC123"
}
```

### 4.2 状态控制

```http
POST /internal/v1/sessions/{session_id}/pause
POST /internal/v1/sessions/{session_id}/resume
POST /internal/v1/sessions/{session_id}/stop
```

`stop` 返回最终产物：

```json
{
  "session_id": "s_01JABC123",
  "status": "finalized",
  "artifacts": {
    "video_path": "/data/sessions/s_01JABC123/input/source.mp4",
    "landmarks_path": "/data/sessions/s_01JABC123/input/landmarks.jsonl",
    "events_path": "/data/sessions/s_01JABC123/live/events.jsonl",
    "summary_path": "/data/sessions/s_01JABC123/live/summary.json"

  "summary": {
    "reps": 12,
    "duration_s": 77.0,
    "mean_confidence": 0.91,
    "alert_counts": {
      "squat_depth_insufficient": 2
    }
  }
}
```

### 4.3 实时画面

```http
GET /live/{session_id}/stream.mjpg
```

- 仅允许本机访问。
- 默认 640x480、15 FPS。
- 骨架、阶段和调试信息由 Live Engine 直接绘制到视频帧。
- 镜端不需要接收关键点坐标即可显示骨架。

### 4.4 实时 WebSocket

```text
ws://127.0.0.1:8020/ws/live/{session_id}
```

服务端消息示例：

```json
{
  "type": "live.metrics",
  "version": "v1",
  "session_id": "s_01JABC123",
  "t_ms": 18320,
  "seq": 172,
  "payload": {
```

`elapsed_s` 为排除暂停时间后的训练时长。两个字段为可选字段，旧客户端可忽略。

```json

```

```json
{

  "version": "v1",
  "session_id": "s_01JABC123",
  "t_ms": 18320,
  "seq": 174,
  "payload": {

```

### 4.5 向 Core 上报低频状态

Live Engine 每秒最多向 Core 上报一次摘要，不发送完整关键点。

```http
POST /api/v1/internal/sessions/{session_id}/state
X-Internal-Token: <internal-token>
```

```json
{
  "status": "active",
  "t_ms": 18320,
  "payload": {
    "exercise": "squat",
    "phase": "up",
    "reps": 8,
    "confidence": 0.93,
    "fps": 24.1,
    "paused": false
  }
}
```

### 4.6 向 Core 提交最终产物

```http
POST /api/v1/internal/sessions/{session_id}/finalize
X-Internal-Token: <internal-token>
```

```json
{
  "artifacts": {
    "video_path": "/data/sessions/s_01JABC123/input/source.mp4",
    "landmarks_path": "/data/sessions/s_01JABC123/input/landmarks.jsonl",
    "events_path": "/data/sessions/s_01JABC123/live/events.jsonl",
    "summary_path": "/data/sessions/s_01JABC123/live/summary.json"
  },
  "summary": {
    "reps": 12,
    "duration_s": 77.0,
    "mean_confidence": 0.91,
    "alert_counts": {
      "squat_depth_insufficient": 2
    }
  }
}
```

Core 校验路径位于允许的 session 目录内，创建离线 job，并返回关联结果：

```json
{
  "session_id": "s_01JABC123",
  "status": "analyzing",
  "job_id": "job_abc123"
}
```

## 5. Core WebSocket

### 5.1 手机客户端

```text
ws://<core-host>:8011/api/v1/ws/client
Authorization: Bearer <pairing_token>
```

消息类型：

- `session.snapshot`
- `session.state`
- `live.metrics`
- `rep.completed`
- `form.alert`
- `report.progress`
- `report.ready`
- `error`

`live.metrics` 在手机端限制为 2–5 Hz，不转发完整关键点。

### 5.2 镜端客户端

```text
ws://<core-host>:8011/api/v1/ws/mirror
Sec-WebSocket-Protocol: vigorsync.v1, vigorsync.token.<mirror_token>
```

Core 发给镜端：

```json
{
  "type": "session.start",
  "version": "v1",
  "session_id": "s_01JABC123",
  "payload": {
    "exercise": "squat",
    "view": "side_left",
    "target_reps": 12,
    "stream_url": "http://127.0.0.1:8020/live/s_01JABC123/stream.mjpg",
    "ws_url": "ws://127.0.0.1:8020/ws/live/s_01JABC123"
  }
}
```

手机修改训练草稿时，Core 还会发送：

```json
{
  "type": "session.config",
  "version": "v1",
  "payload": {
    "exercise": "squat",
    "view": "front",
    "target_reps": 12
  }
}
```

手机点击训练总结页的“返回主页”时，Core 发送：

```json
{
  "type": "session.dismissed",
  "version": "v1",
  "session_id": "s_01JABC123",
  "payload": {
    "status": "analyzing"
  }
}
```

手机删除历史记录后，Core 向手机和镜端广播：

```json
{
  "type": "session.deleted",
  "version": "v1",
  "session_id": "s_01JABC123",
  "payload": {}
}
```

镜端发给 Core：

```json
{
  "type": "mirror.state",
  "version": "v1",
  "payload": {
    "state": "training",
    "session_id": "s_01JABC123"
  }
}
```

## 6. 数据文件

### 6.1 `landmarks.jsonl`

每行一帧：

```json
{
  "t_ms": 18320,
  "frame": 549,
  "width": 640,
  "height": 480,
  "pose_confidence": 0.94,
  "landmarks": [
    {"id": 0, "x": 0.51, "y": 0.12, "z": -0.02, "visibility": 0.99}
  ]
}
```

第一版不要求逐帧保存 world landmarks；如需 3D 指标，由离线阶段重新提取。

### 6.2 `events.jsonl`

保存 rep、告警、暂停、恢复和错误事件。格式与 API 事件一致，必须带 `seq` 和 `t_ms`。

## 7. 错误码

| 错误码 | 含义 |
| --- | --- |
| `unauthorized` | token 缺失或无效 |
| `session_not_found` | 会话不存在 |
| `invalid_transition` | 当前状态不允许该命令 |
| `camera_busy` | 摄像头被占用 |
| `camera_open_failed` | 摄像头无法打开 |
| `pose_model_load_failed` | Pose 模型加载失败 |
| `live_engine_unavailable` | 实时引擎不可达 |
| `recording_failed` | 视频落盘失败 |
| `analysis_enqueue_failed` | 离线任务创建失败 |
| `report_not_ready` | 报告尚未生成 |
| `internal_error` | 未分类内部错误 |

### 7.1 实时告警码

`form.alert.payload.code` 和告警计数键必须使用下列固定值：

| 动作 | 告警码 |
| --- | --- |
| 深蹲 | `squat_depth_insufficient`、`squat_torso_lean_excess`、`squat_knee_valgus`、`squat_asymmetry`、`squat_tempo_inconsistent`、`squat_stability_low` |
| 俯卧撑 | `pushup_depth_insufficient`、`pushup_body_line_break`、`pushup_hip_sag`、`pushup_hip_pike`、`pushup_elbow_flare`、`pushup_asymmetry`、`pushup_tempo_inconsistent`、`pushup_stability_low` |

`form.alert.payload.joints` 可选，用于镜端和 Live Engine 高亮问题关节。取值为
`left/right_shoulder`、`left/right_elbow`、`left/right_wrist`、
`left/right_hip`、`left/right_knee` 或 `left/right_ankle`。

## 8. 契约文件与校验

| 文件 | 作用 |
| --- | --- |
| `packages/contracts/common.schema.json` | ID、枚举、置信度、摘要、产物和错误信封 |
| `packages/contracts/session.schema.json` | Core 对手机和镜端返回的会话记录 |
| `packages/contracts/live-event.schema.json` | WebSocket 与 `events.jsonl` 的实时事件 |
| `packages/contracts/session-summary.schema.json` | Live Engine 最终 `summary.json` |
| `packages/contracts/landmark-frame.schema.json` | `landmarks.jsonl` 的单帧记录 |
| `packages/contracts/session-state-machine.schema.json` | 状态机迁移表结构 |
| `packages/contracts/session-state-machine.json` | 会话状态迁移的唯一权威表 |
| `packages/contracts/openapi.yaml` | Core API、Live Engine REST、内部接口和 WebSocket 端点 |
| `packages/contracts/examples/` | 可执行校验的契约样例 |

工作区根目录提供了 `.venv`，契约校验不依赖网络：

```bash
cd VigorSync
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-contracts.txt
.venv/bin/python scripts/validate_contracts.py
.venv/bin/python -m unittest discover -s tests/contracts -v
```

也可以使用 `make check`。校验器会检查 JSON Schema 自身、跨 Schema `$ref`、全部示例、状态机可达性和终态约束、OpenAPI 路径、幂等键与相对引用。

## 9. 契约版本

- API 版本：`/api/v1`。
- WebSocket 消息必须带 `type`；当前消息若携带 `version`，值必须为 `v1`。
- JSON Schema 放在 `packages/contracts/`。
- 后端先定义 schema，再生成 OpenAPI 和客户端模型。
- 破坏性变更必须升级 URL 或消息版本，不允许静默修改字段语义。
